# cpnos-in-c PROM1-only: push TPA from 55 K to 56 K

**Status:** TODO (deferred from session 73j-locale on 2026-05-17).

## Goal

Boot banner reports "56K" instead of "55K".  Concretely:
`CPNOS_TPA_KB = (NDOS + 0x22) / 0x400` must round up to 56, so
`NDOS >= 0xDFDE`.  cpnos-build's `CODE_BASE` (currently `LDD80` =
0xDD80) needs to move to at least `LE080` (= 0xE080), which gives
`NDOS = 0xE083` → TPA_KB = 56.

## What blocks it

`CODE_BASE = 0xE080` puts cpnos.com's CODE region at 0xE080..0xECFF.
That overlaps two BSS sections that currently live in the
0xEA00..0xECFF "free RAM between cpnos.com end and resident BIOS"
gap:

  * `__scratch_bss` at 0xEB00..0xEB3F (64 B used) -- PIO/keyboard
    counters, cursor state, per-function static frames, transport
    flags.  Lives on the .scratch_bss page.
  * `_pio_rx_buf` at 0xEC00..0xECFF (256 B page-aligned IRQ ring).
    Page-aligned so the ISR's hot path uses `LD H, page; LD L, tail`
    to add the head/tail offsets without a 16-bit add.

Both must vacate before CODE_BASE can move up.

## Possible relocation targets

1. **Shrink pio_rx_buf 256 -> 128 B + move into the resident gap.**
   memory_map.md notes a 150 B gap at 0xF66A..0xF6FF; the locale
   tables (this session's 73j-locale work) filled that gap.  With
   pio_rx_buf at 128 B and locale tables at 0xF680, there is no
   room.  Need to either: (a) collapse pio_rx_buf and locale tables
   into the same page (e.g., pio_rx_buf 0xF600..0xF67F, locale 0xF680..
   0xF7FF -- 128 B for pio_rx_buf is tight under CP/NET 137 B frames),
   or (b) move locale tables up to 0xF700..0xF7FF (256 B; drops
   outcon to save 128 B by overlapping it with inconv lower-half --
   rcbios-incompatible).

2. **Move scratch_bss + pio_rx_buf into the resident region itself.**
   Resident is 2417 B used of 2432 B (37 B free in PROM1-only after
   locale tables landed).  Cannot fit 320 B of BSS there.

3. **Move CODE_BASE up only partially and accept "55K+a-bit".**  No
   gain in reported TPA -- the floor() in TPA_KB formula stays at
   55 until NDOS >= 0xDFDE.  Worthless.

4. **Reverse Path 5/6 (move resident base back up to 0xEE00).**  In
   path 3 we used CODE_BASE = 0xE180, NDOS = 0xE183, and TPA reported
   as ~57K (rounding artifact).  But that required resident at
   0xEE00..0xF6FF, which is 256 B less than today.  Resident shrank
   on path 5 specifically because BSS needs grew.  Going back means
   shrinking resident.

5. **Shrink _msg buffer (200 B -> 175 B per memory_map.md note)
   and combine with smaller pio_rx_buf.**  Saves ~25 B from cfgtbl
   region (already moved to 0xF53C); not enough alone.

## Cost class

Medium-to-Hard.  Mechanical CODE_BASE bump is one line, but the
BSS relocation cascade touches: linker scripts (clang + SDCC),
transport_pio.c (ISR hot path if pio_rx_buf shrinks), payload.ld
ASSERTs, and the PROM1-only `clang-prom1lineprog/payload.ld`
overlay.  All four cells (clang/sdcc x PIO/SIO) plus PROM1-only
must regression-test.

Rebuilding cpnos-build via VirtualCpm RMAC+LINK takes ~10s and
emits a new `cpnos.sym` -- the Makefile already auto-extracts
addresses into cpnos_addrs.h, so the C side reflows automatically.

## When

Pick up the next time PROM1 budget allows the shrinkage or when
TPA size is actually constraining a user-mode program.  PolyPascal
PRIMES runs comfortably in 55 K; CP/NET applications rarely hit
the TPA top.
