# cpnos-in-c SDCC PROM1-only line program

**Status:** WORKING.  Boots to E>; polypascal-test PASSes in ~50 s.

`make prom1-lineprog COMPILER=sdcc` produces
`sdcc-prom1lineprog/prom1-lineprog.bin` (~2246 B, 4 KB padded for
the MAME PROMCFG=2 / 4 KB-prom default).  Doesn't fit a 2 KB
physical PROM1 socket yet; see follow-up TODO for shrinking.

## Build pipeline (two-pass)

  1. **pass 1:** zcc -create-app links SDCC objects with
     sdcc-prom1lineprog/sections.asm (INIT_CODE at 0xC000,
     RESIDENT chain at 0xED00) + sdcc-prom1lineprog/bootstrap.asm
     + dzx0_standard.asm + EMPTY init_zx0.asm / payload_zx0.asm
     placeholders.  Emits per-section .bin (cpnos_lp_INIT_CODE.bin
     at VMA 0xC000, cpnos_lp_RESIDENT_JUMPTABLE.bin at VMA 0xED00).
  2. **patch:** patch_payload_checksum.py overwrites the last 2 B of
     cpnos_lp_RESIDENT_JUMPTABLE.bin so word-additive sum = 0xCAFE
     (matches clang's flow; future relocator-side verify hook can
     check it post-dzx0).
  3. **ZX0:** z88dk-zx0 compresses both bins, z88dk-dzx0 roundtrip-
     verifies them.
  4. **pass 2:** zcc relinks; INCBIN in init_zx0.asm /
     payload_zx0.asm pulls the real compressed bytes.
  5. **pad:** sdcc-prom1lineprog/prom1-lineprog.bin = pass-2's
     cpnos_lp_LINEPROG_HEADER.bin padded to 4 KB.

## Final layout (LMA 0x2000)

  | Offset  | Bytes | Contents                                |
  |---------|-------|-----------------------------------------|
  | 0x2000  | 2     | bootstrap_entry word = 0x2008           |
  | 0x2002  | 6     | " RC702" signature (autoload contract)  |
  | 0x2008+ | ~30   | bootstrap.asm code                      |
  | +       | ~69   | dzx0_standard decoder                   |
  | +       | 585   | init.zx0 (INIT_CODE 689 -> ZX0)         |
  | +       | 1559  | payload.zx0 (RESIDENT 2192 -> ZX0)      |
  | total   | ~2246 | (+ 0xFF padding to 4096)                |

## What the build needs that's not in this directory

  * `sdcc/cpnos_polypascal_addrs.lua` -- generated at build time
    from sdcc/cpnos_lp.map; gives polypascal_test.lua the
    kbd_head + kbd_ring addresses for direct keystroke injection.
    Currently NOT auto-generated by the Makefile -- regen manually:

    ```
    KH=$(awk '/^_kbd_head[ \t]+=[ \t]+\$/ {gsub(/.*\$|[ \t].*/,"",$0); print $0}' sdcc/cpnos_lp.map)
    KR=$(awk '/^_kbd_ring[ \t]+=[ \t]+\$/ {gsub(/.*\$|[ \t].*/,"",$0); print $0}' sdcc/cpnos_lp.map)
    printf 'return {\n  kbd_head = 0x%s,\n  kbd_ring = 0x%s,\n}\n' "$KH" "$KR" \
        > sdcc/cpnos_polypascal_addrs.lua
    ```

  * MAME with PROM1 set to 2732/4KB.  ravn/mame master
    sets that default since session 73j-late.

## Compiler-emit caveat resolved this session

SDCC's z88dk back-end silently drops function-scope `extern`
declarations from its `.asm` GLOBAL list; the resulting object
references undefined symbols and z80asm errors out.  Caught while
diagnosing the netboot "stall" (which was really a stale-object
masquerade -- the build never rebuilt cpnos_main.o, so the slave
ran pre-locale-machinery code).  Fix in cpnos:
`extern void install_locale_tables(void);` at file scope in
cpnos_main.c, `extern uint8_t *get_img_base(void);` at file scope
in init.c.  Bug filed at https://github.com/ravn/z88dk/issues/7.
